# Evolution Item System Spec (Gen 1-5)

## 범위

- 대상 도감 범위는 `#1-#649`이다.
- 리전폼, 폼 전용 진화, Gen6+ 신규 포켓몬으로의 진화는 v1 범위에서 제외한다.
- 일반 레벨 진화는 원작 `min_level`을 따른다.
- 조건을 만족해도 자동 진화하지 않고, 사용자가 `진화` 버튼을 눌러 실행한다.

### 추가 스프라이트

- `linking-cord`는 PokeAPI item API에는 있으나 한국어명과 기본 스프라이트가 없다.
- `연결의끈` 이름은 앱 내부 정적 매핑으로 제공한다.
- `public/vendor/pokeapi-sprites/sprites/items/linking-cord.png` 또는 별도 앱 에셋 경로에 1개 픽셀 아이콘을 추가해야 한다.
- 나머지 25개 아이템 스프라이트는 현재 로컬 PokeAPI sprites checkout에 존재한다.

## 토큰 보상 기준

아이템 보상은 실제 사용량 체감과 맞추기 위해 `total_tokens` 전체를 기준으로 한다.

```text
10,000 totalTokens마다 itemPoints +1
```

- 캐시 재사용 토큰도 실제 세션 사용량에 포함되므로 별도로 차감하지 않는다.
- `rewardTokens`/`effectiveTokens` 값이 함께 들어와도 포인트 적립에는 `totalTokens`를 우선 사용한다.

## 뽑기 규칙

```text
10,000 totalTokens마다 itemPoints +1
itemPoints 250점으로 1회 뽑기
성공률 30%
실패 시 포인트 환급 없음
```

아이템 획득에 성공했을 때:

```text
픽업 아이템이 설정되어 있음:
  15% = 픽업 아이템
  85% = 나머지 25개 아이템 균등

픽업 아이템이 설정되어 있지 않음:
  26개 아이템 균등
```

Target ticket:

```text
픽업 설정 있음 + 아이템 획득 성공 + 픽업 아이템이 아님:
  targetTicket +1

꽝:
  targetTicket 없음

픽업 아이템 획득:
  targetTicket 없음
```

교환비:

```text
랜덤 뽑기: 일반 포인트 250
아이템 판매: 일반 포인트 +10
일반 포인트 지정 구매: 삭제
Target 확정 획득: targetTicket 20
```

`연결의끈`은 다른 아이템과 동일 확률, 동일 판매가, 동일 target ticket 확정 획득 비용을 사용한다.

## 리크루트 포인트 비용

리크루트는 `itemPoints`를 사용한다. 도감에 이미 등록된 포켓몬은 후하게, 미등록 포켓몬은 신규 발견 프리미엄을 붙여 비싸게 책정한다. 미등록 포켓몬을 리크루트하면 구매 성공 시 도감에 등록된다.

| 최종 희귀도 티어 | 등록됨 | 미등록 |
|---|---:|---:|
| 1 | 100 | 500 |
| 2 | 300 | 1,500 |
| 3 | 700 | 3,500 |
| 4 | 1,000 | 5,000 |
| 5 | 2,000 | 10,000 |

## 진화 처리 규칙

- 원작 `use-item` 진화는 해당 아이템 1개를 소비한다.
- 원작 순수 `trade` 진화는 `연결의끈` 1개를 소비한다.
- 원작 `trade + held_item` 진화는 원작 소지아이템 1개만 소비한다. `연결의끈`은 추가로 요구하지 않는다.
- 원작 `held_item + level-up` 진화는 원작 소지아이템 1개를 소비한다. 시간 조건은 제거한다.
- 아이템으로 대체할 수 없는 친밀도, 기술, 성별, 스탯, 파티, 아름다움 조건은 v1에서 별도 시스템을 만들지 않고 레벨/분기 선택으로 단순화한다.
- 동일 진화에 원작 조건이 여러 개 있으면 아이템 조건을 우선한다. 예: 레어코일/코코파스의 장소 진화보다 `천둥의돌`을 우선한다.

### 레벨 대체 보정

- 특수 진화표에 포함된 베이비 포켓몬의 친밀도/기술 대체 진화는 기본 `Lv.10`으로 둔다.
- 특수 진화표에 없는 일반 레벨 베이비는 원작 레벨을 유지한다.
- 명시 예외: 타만타는 `Lv.20`, 먹고자와 리오르는 `Lv.30`으로 둔다.
- 배루키는 원작 분기 구조를 살리기 위해 `Lv.20` 후보 선택으로 둔다.
- 핑복은 `동글동글돌` 소비 진화로 둔다.
- 골뱃, 럭키, 두르쿤처럼 최종/후반 보상감이 필요한 친밀도 진화는 `Lv.36`으로 둔다.
- 에브이/블래키는 원작 친밀도+시간 조건 대신 각각 `태양의돌`/`달의돌`로 매핑한다. 원작과는 다르지만, v1의 아이템 진화 일관성과 UI 직관성을 우선한다.

## 구현 메모

- 인벤토리는 `{ itemId: count }` 형태로 충분하다.
- 재화는 `itemPoints`, `targetTickets`, `rewardTokenRemainder`, `pullHistory`를 저장한다. 기존 저장 데이터의 `pickupPoints`는 `targetTickets`로 마이그레이션한다.
- 픽업은 `pickupItemId: string | null` 하나만 둔다.
- UX상 추천은 10,000 totalTokens 단위의 포인트 progress bar + 사용자가 `뽑기` 버튼으로 250포인트를 소모하는 방식이다.
- 진화 후보가 여러 개인 경우, 가능한 후보를 모달에 보여주고 사용자가 선택한다.
